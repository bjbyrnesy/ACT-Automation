# Opt-in host data-plane addressing

**Date:** 2026-11-24  
**Status:** approved design  
**Approach:** Clab node hooks at generate/attach (exec / bind + script)

## Summary

Operators may opt in, when attaching a Linux host, to a unique data-plane IPv4
on a lab subnet (default `192.168.2.0/24`) with a gateway (default
`192.168.2.1`). The intended lab pattern is CloudVision-owned fabric: VLAN 2
access (or MLAG LACP Port-Channel) toward the host and an SVI at
`192.168.2.1/24`, so hosts can ping each other and the gateway without further
manual Linux addressing.

ACT/clab configure **host side only**. Switch Port-Channels, VLANs, and SVIs
remain CloudVision / operator owned.

## Decisions (locked)

| Topic | Choice |
|-------|--------|
| Enablement | **Opt-in** per attach (`host_net` / `--host-net`), not on by default |
| Single-homed | IP + gateway on **`eth1`** |
| Dual-homed | LACP **`bond0`** (802.3ad), IP + gateway on bond; slaves `eth1`/`eth2` |
| Switch Po / LACP / VLAN | **Not** generated by ACT — configure in CloudVision |
| Lab defaults | `HOST_NET_SUBNET` / `HOST_NET_GATEWAY` in Web UI / labs settings |
| Per-attach overrides | Optional host IP, subnet, gateway |
| Allocation | Auto next free in subnet (skip network, broadcast, gateway) unless IP set |
| Apply mechanism | Clab `exec` and/or bind of an idempotent script from the repo |
| Docs | `/root/HOST-NET.md` (and optional `/root/HOST-NET.env`) when enabled |

## Goals

- Quick L2/L3 reachability between hosts and an SVI after CVP access/VLAN setup.
- Unique per-host addresses within a topology when `host_net` is enabled.
- Clear in-guest documentation for changing IP and using multitool / mcast tools.
- No dependency on rebuilding the host image for v1 script/doc changes.

## Non-goals

- Emitting cEOS / Arista Port-Channel, VLAN, or SVI config from ACT.
- ACT `generic` VM data-plane networking (v1 targets **clab `kind: linux`** hosts).
- Active-backup bonding (LACP only for dual-home).
- Enabling host_net by default for every attach.

## Lab settings

Allowlisted keys beside existing `CLAB_*` (see `acta/web/settings_api.py`):

| Key | Default | Role |
|-----|---------|------|
| `HOST_NET_SUBNET` | `192.168.2.0/24` | Default data-plane prefix |
| `HOST_NET_GATEWAY` | `192.168.2.1` | Default gateway (expected SVI) |

These seed attach when the operator enables host net but does not override.

## Attach surface

### CLI

```text
acta attach host NAME TOPOLOGY … --host-net
acta attach host NAME TOPOLOGY … --host-net --host-ip 192.168.2.10
acta attach host NAME TOPOLOGY … --host-net --host-subnet 192.168.2.0/24 --host-gateway 192.168.2.1
```

### API / UI

`POST /api/attach` gains optional fields: `host_net` (bool), `host_ip`,
`host_subnet`, `host_gateway`. Attach page: checkbox “Data-plane IP” plus
advanced fields for IP / subnet / gateway (placeholders from lab settings).

### Validation

- `host_net` false → ignore IP/subnet/gateway fields.
- Subnet must be IPv4 prefix; gateway must lie in subnet.
- Explicit `host_ip` must be in subnet, not network/broadcast/gateway, and not
  already used by another `host_net` host in the topology.
- Dual-homed attach with `host_net` expects two data uplinks (`eth1`, `eth2`)
  for the bond; single-homed uses `eth1` only.

## Allocation

1. Resolve effective subnet/gateway (attach override → lab settings → defaults).
2. If `host_ip` omitted, pick the lowest free host address in the subnet
   excluding network, broadcast, and gateway, among addresses already claimed
   by hosts in this topology with host net enabled (ACT metadata and/or clab
   labels / annotations).
3. Persist the assigned address with the host so show/UI can display it.
4. Detach releases the address.

## Clab node shape (when `host_net` enabled)

Retain existing linux jumphost defaults (`mgmt-ipv4`, host image, `lldpd`).

Add an idempotent bootstrap (preferred: bind a script from the acta checkout
or generated lab dir, then `exec` it; alternatively inline `exec` commands):

**Single uplink**

- Ensure `eth1` is up.
- Assign `host_ip/prefix` on `eth1`.
- Default route via gateway (replace existing default on that table if needed).

**Dual uplink (MLAG dual-homed)**

- Create `bond0` mode `802.3ad` (LACP).
- Enslave `eth1` and `eth2`.
- Assign `host_ip/prefix` and default route on `bond0`.

Do **not** configure switch-side members. Document that CloudVision must
provide a matching LACP Port-Channel (or equivalent) and VLAN/SVI.

Also write:

- `/root/HOST-NET.md` — operator-facing guide (see below).
- Optional `/root/HOST-NET.env` — `HOST_IP`, `PREFIX`, `GATEWAY`, `IFACE=eth1|bond0`
  for copy-paste and future tooling.

Re-attach / re-exec must be safe (idempotent addr/bond setup).

## `/root/HOST-NET.md` contents

- Current address, interface (`eth1` or `bond0`), subnet, gateway.
- Assumed lab story: VLAN 2 (or lab VLAN) + SVI at gateway; mgmt plane remains
  clab `mgmt-ipv4` (typically `172.100.100.0/22`) and is separate.
- How to change IP / gateway with `ip addr` / `ip route` (and that ACT may
  overwrite on redeploy/exec unless disabled).
- Dual-home: LACP on `bond0`; Port-Channel lives in CloudVision.
- Available tools (from multitool + image layers), including at least:
  - connectivity: `ping`, `traceroute`, `curl`, `dig` / DNS tools as present
  - LLDP: `lldpcli` / `lldpd` as present
  - multicast: `mcast-send`, `mcast-receive`, `mcast-status`
- Pointer that host image is `acta-host-multitool` (network-multitool + mcast-tools).
